# Реестр дочерних компаний

Источник данных для страницы каталога:
https://tomas-mts.github.io/mts-landing/companies.html

Файл `companies.xlsx` парсится в браузере через [SheetJS](https://github.com/SheetJS/sheetjs) при загрузке страницы. Никакого backend нет — обновление реестра происходит через коммит обновлённого xlsx в репозиторий.

## Как обновить реестр

1. Открой `companies.xlsx` в Excel (или совместимой программе — LibreOffice Calc, Numbers).
2. На листе **«Компании»** добавь / измени / удали строки.
3. **Не меняй** заголовки колонок — они привязаны к коду парсера.
4. Сохрани файл в формате `.xlsx` (не `.xlsb`, не `.xls`).
5. Закоммить и запушь:
   ```sh
   git add data/companies.xlsx
   git commit -m "Update companies registry"
   git push
   ```
6. GitHub Pages обновит лендинг за 1–2 минуты.

## Структура листа «Компании»

25 колонок, заголовок в первой строке:

| Колонка | Тип | Назначение |
|---|---|---|
| `id` | text | Уникальный идентификатор латиницей через дефис. Используется в URL (`?company=alfa-link`). Без него строка **игнорируется**. |
| `короткое_название` | text | Бренд / короткое имя в карточке. |
| `юр_форма` | text | ООО, АО, ПАО и т.п. |
| `отрасль` | text | Из словаря (см. ниже). Нет в словаре — карточка рендерится, но без цветного тега. |
| `регион` | text | Город. |
| `сотрудников` | int | Целое число. Бьётся по бакетам S/M/L/XL автоматически. |
| `год_основания` | int | 4 цифры. |
| `ИНН` | text | **Формат «текст»**, иначе ведущие нули потеряются. |
| `ОГРН` | text | То же. |
| `юр_адрес` | text | |
| `сайт` | text | Полный URL с протоколом (`https://...`). В модалке отображается как ссылка. |
| `ген_директор` | text | |
| `гл_бухгалтер` | text | |
| `отв_за_интеграцию` | text | |
| `ERP`, `HR_система`, `CRM`, `почта`, `BI` | text | Названия систем. Пусто или `—` отрисовывается как «Не используется». |
| `статус_интеграции` | enum | См. ниже. |
| `прогресс_HR` / `прогресс_IT` / `прогресс_финансы` / `прогресс_юр` / `прогресс_безопасность` | enum | Прогресс по 5 блокам. |

## Допустимые значения

### `статус_интеграции`

| Значение | Подпись на странице | Цвет |
|---|---|---|
| `planned` | Запланировано | серый |
| `in_progress` | В работе | оранжевый |
| `completed` | Завершено | зелёный |
| `paused` | Приостановлено | красный |

### `прогресс_*` (HR / IT / финансы / юр / безопасность)

| Значение | Подпись | Цвет |
|---|---|---|
| `not_started` | Не начато | серый |
| `in_progress` | В работе | оранжевый |
| `completed` | Завершено | зелёный |

### `отрасль` — словарь цветных тегов

`Телеком и связь`, `Финтех и платежи`, `Медиа и контент`, `Облачные сервисы`, `Кибербезопасность`, `Аналитика данных`, `AI и машинное обучение`, `Рекламные технологии`, `EdTech и онлайн-образование`, `IoT и M2M-решения`, `E-commerce и retail`, `Игры и киберспорт`.

Любое другое значение тоже отрисуется, но без цветного тега. Если нужен новый цвет — добавить в `companies.css` (секция «Industry tags») и `INDUSTRY_TO_CLASS` в `companies.js`.

## Что делать НЕ нужно

- ❌ Переименовывать колонки.
- ❌ Писать русское название статуса в `статус_интеграции` (только английские enum).
- ❌ Оставлять пустую `id` — такие строки игнорируются парсером.
- ❌ Добавлять формулы в ячейки — парсер берёт сырое значение, не результат.
- ❌ Сохранять как `.xlsb` или `.csv` — только `.xlsx`.

## Лист «Справочник»

Второй лист в файле — для авторов реестра. Парсер его игнорирует, можно туда писать что угодно (типовые значения, контакты, заметки).
